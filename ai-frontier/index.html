能力曲线还在上升，日常生活与判断力却拖住后腿

编辑判断：

两份新评估共同显示：模型在可验证任务上的能力仍快速提升，但个人Agent在日常任务与开放式判断任务上失败率高、一致性差，能力提升尚未转化为可靠性与安全。

为什么现在看：

2026年11月20日，MIT Technology Review报道METR更新其时间跨度图，新增开放式判断任务；11月24日，TechCrunch报道ShellBench显示顶尖模型失败超三分之一、15.7%尝试至少违反一项安全要求，同期Muse等个人Agent正快速普及。

材料陈述

发生了什么

2026年11月20日，MIT Technology Review 报道了 AI 评估非营利组织 METR 对其“时间跨度”图的更新：新报告称部分 AI 能力仍沿指数轨迹提升，前沿模型能完成的任务长度约每四个月翻倍，但在需要判断的开放式任务上模型表现不及其在编程等领域。METR 增加了人类耗时更长的任务和更开放的任务，结果显示没有一个由 AI 设计的评估被其员工认为可用于研究，模型在哲学论证打分上也低于人类；不过最新模型在评估设计任务上已接近及格线。此前四天，TechCrunch AI 于11月24日报道，ShellBench 新基准显示 OpenAI、Anthropic 和 Meta 的最先进模型在日常个人任务中失败超过三分之一，所有模型测试中15.7%的尝试至少违反一项安全要求；最高分的 GPT-6 Astra 在三次相同条件下全部成功的概率不到一半。该基准由 OpenClaw Foundation、Parsewave、Hugging Face、Red Hat 和 UC Berkeley 研究者合作开发，基于逾1000万条匿名真实交互。

MIT Technology Review ↗TechCrunch AI ↗
分析判断

为什么会这样

机制上，可验证任务能通过自动判定对错来做强化学习，反复强化成功路径，所以模型在编程和数学上提升明显（MIT Technology Review 引述的机制解释）。日常个人任务和开放式判断任务的成败标准模糊、反馈慢，难以套用同一套训练与评估方法，模型因此容易在多步流程里出错。具体到 ShellBench，任务是跨邮件、日历、收据等杂乱信息完成安排，例如安排接孩子放学，资料显示模型在这一点上失败率为79.5%，说明问题多出在信息筛选、隐私边界和步骤串联等难以自动校验的环节，并非只会写代码。分析：模型选择影响更大，但在更强的模型上，harness 的影响上升，意味着可靠性不仅取决于模型，还取决于编排与工具调用方式。

分析判断

放在一起怎么看

放在一起看，两份材料互为补充而非彼此矛盾：METR 从任务时长角度证明可验证能力仍在指数提升，ShellBench 则从真实个人任务角度暴露这种提升尚未传导到多步、含隐私与安全边界的日常场景，两者共同支撑“能力提升未转化为可靠性”的判断。分歧在解释上：METR 报告称开放式任务难以量化、难以外推趋势（Matt Putz 观点），而 ShellBench 给出了具体失败率与一致性数据，说明工程侧已可度量部分风险。对行业而言，分析：这意味着厂商宣传的 Agent 能力与用户实际体验之间仍存在缺口，产品方应把 harness 编排、权限隔离与重复运行稳定性当作上线前的硬指标，而非只看基准分数。

证据边界

还有什么不能下结论

仍不能下结论的地方在于：两份材料都不足以证明失败率是长期趋势或产品定论。ShellBench 明确说明未在 Muse、Dots、Claude Duet 等产品的原生 harness 中测试，结果未必代表消费者实际体验，且数据来自匿名交互，样本构成未知；METR 也承认开放式任务难以设计和评分，纳入数量少，Matt Putz 称难以建立像可验证任务那样干净的量化趋势。厂商自报方面，Meta 称 Muse 上线六周在美加有超1000万人设置，但这是厂商口径，非独立验证。结论只适用于所测模型、任务与 harness 组合，不能外推到全部个人 Agent 或全部日常场景。

为什么会这样

机制上，通用模型是把蛋白质设计拆成可用语言描述、可用代码验证的推理步骤，而不是依赖某个专用模型固定下来的输入输出接口。以材料中 GPT-6.2 设计结合 IL-7Rα 的小蛋白为例，它先提出两种蛋白可能如何相互作用，再写代码探索不同形状和氨基酸选择，最后检查两者能否嵌合，整个过程通过改提示切换任务，无需重新训练。这说明通用模型的优势来自把数学、物理、化学和序列模式知识组织成可执行的推理链，再加上通用代码工具做搜索与校验，因此能覆盖多类任务。但材料也显示预测完整蛋白质结构仍是明显弱项，实验中的序列供给和候选筛选仍借助专用模型，且结合证据只是初步实验室结果，所以这种能力能否稳定外推仍是未知。

生态连接和按需加载工具能降低个人 Agent 接入成本与上下文负担，但 ShellBench 显示“能办成且办得稳”仍是主要瓶颈，工程瓶颈尚未被这两项能力单独解决。

发生了什么

2026年11月19日，Google 在 Gemini API 的 Interactions API 中预览 Tool Retrieval，允许开发者按需加载工具参数 schema以降低输入 token 与延迟；据 Google AI 博客，该功能配合 Gemini 3.6 及之后模型，也可用于远程 MCP server。四天后的11月24日，爱范儿报道豆包推出个人智能体「小豆」，采用邀请制，主打主动服务与持续办事，依托抖音内容、电商、生活服务及飞书办公生态，并提供应用连接与出行、办公等插件。同日 TechCrunch 报道 ShellBench 基准，称 OpenAI、Anthropic、Meta 的最先进模型失败率超过三分之一。

分析判断

为什么会这样

按需加载工具解决的是“模型看得到哪些工具”，主动办事难在“模型能不能在多步任务里做对且做稳”。以 Gemini 为例，模型仍能看到被延迟工具的 name 和 description，需要时再让 API 载入参数 schema（Google AI 博客）；这压缩的是上下文和成本，不改变模型对任务状态、隐私边界和风险后果的判断。ShellBench 给出的具体例子是：研究者让 Agent 处理含邮件、日历、收据混在一起的日常事务，结果约 10% 本可成功的尝试仍违反至少一项安全要求，例如漏掉孩子放学接送在相关任务中占 79.5%（TechCrunch 报道）。这说明生态连接只把数据接进来，不保证 Agent 分清哪些信息该用、哪些动作该停；小豆的代打电话等场景也取决于对方回答和线下条件，爱范儿体验称其暂不支持私人号码拨打。因此工程瓶颈在于多步执行中的一致性与安全约束，属机制分析。

仍不能下结论的至少有四点。其一，METR报告纳入的判断型任务数量很少，报道称这类任务设计难、打分难，因此无法据此判断模型在该方向是否延续指数趋势；METR技术成员Putz也认为，难以验证的任务恐怕无法建立像易验证任务那样干净稳健的趋势。其二，Mollick对Fable 5.2的评测属于个人使用体验，且他明确表示在业务能否真正运营前就中止了实验，这不能替代独立、可复现的评测。其三，目前缺少厂商自报能力与第三方独立验证之间的系统对照，OpenAI在博客中自述其模型在真实工作任务上不如在易验证任务上表现好，这仍是厂商自报。其四，现有证据只覆盖特定模型与少数任务，不能推出开放式任务能力普遍落后或终将追平。
